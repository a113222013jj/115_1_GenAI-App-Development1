# 第 8 週｜社團公告整理小幫手設計與驗收紀錄

> 請以實際測試結果更新本紀錄；尚未測試的項目請保留「未測」，不要把模擬或範例結果記成真實 API 成果。不得在此記錄金鑰或個資。

## 一、問題與設計

| 項目 | 設計 |
|---|---|
| App 名稱 | 社團公告整理小幫手 |
| 目標使用者與情境 | 社團社員收到較長活動公告時，想快速找到參加活動所需資訊與下一步。 |
| 一個主要任務 | 將貼上的社團公告整理成活動資訊、報名方式、社員待辦與公告缺漏提醒。 |
| 輸入 | 一段最多 6000 字元的公告文字；測試時使用虛構或已獲授權內容。 |
| 資訊不足如何處理 | 不推測或補造。缺少的單值欄位標示「原文未提及」，清單列出影響參加／報名判斷的缺漏。 |
| 起點與改造 | 以課堂 Pydantic starter 為起點，改成社團公告的任務規則、欄位、標籤、表單文案與本專題 README。 |
| Structured Outputs 路線 | Pydantic，使用 `responses.parse(text_format=ProjectResult)`。欄位以模型類別集中描述並由 SDK 產生 strict Schema。 |
| 個人設計重點 | 不只摘要公告，而是支援社員採取行動：清楚拆出報名截止、報名方式、待辦與缺漏提醒。 |

## 二、輸出欄位契約

| 欄位 | 型別 | 用途 | 畫面標籤 | 人工核對方式 |
|---|---|---|---|---|
| `event_name` | 必填 `str` | 辨識活動 | 活動名稱 | 確認活動名稱出現在原文 |
| `event_date_time` | 必填 `str` | 安排時間 | 活動日期與時間 | 核對原文日期、時間；不得補年份或自行推算 |
| `location` | 必填 `str` | 確認活動地點 | 活動地點 | 確認原文有提到該地點；缺漏應標示未提及 |
| `registration_deadline` | 必填 `str` | 避免錯過報名 | 報名截止時間 | 核對原文明確的截止日期與時間 |
| `registration_method` | 必填 `str` | 知道如何報名 | 報名方式 | 核對原文提供的表單、聯絡方式或其他流程 |
| `participant_actions` | 必填 `list[str]` | 整理社員下一步 | 社員待辦 | 每項動作都須能在原文找到根據 |
| `missing_information` | 必填 `list[str]` | 顯示需向主辦方確認的資訊 | 公告尚缺資訊 | 確認所列資訊確實未在原文出現且有助判斷參加／報名 |

所有欄位必填、禁止額外欄位；文字不得為空白，清單項目不得為空白。空清單表示原文沒有符合該欄的項目。
